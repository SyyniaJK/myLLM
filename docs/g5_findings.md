# G5：主要发现与去留判断

完成日期：2026-10-28。正式数据位于 `results/g5`，数值执行版本为 `8fa19d946f5a7266e59c24b09a0afc50a632cabd`。这是当前解析模型中的诊断，不是真实 GPU 或无线网络测试，也未证明新颖性。

## 最值得保留的结果

**服务量达到条件最优时，能耗仍有改善空间；但固定基线会显著稀释总体收益。**

在同一组六请求、0 dB、SLO=2 秒的控制中，grouped 和 mixed 均成功服务六个请求。按长度分组后，完整 GPU 增量由 **35.038 J 降至 20.538 J，下降 41.38%**；加入相同的 **540 J 固定空闲基线**以及射频能耗后，窗口总能耗仅由 **575.041 J 降至 560.541 J，下降 2.52%**。

单次放置精确枚举也给出相近结论：在 0 dB 的三个 SLO 条件下，均衡和 cap 贪心都能达到六个成功请求，但平均完整变量能耗仍比同服务数前沿多 **14.501 J**。因此，“Goodput 已接近最优”不代表“同服务量能耗已优化”。这些差距来自当前模型的 padding/最长输出结构，长度分组本身已有大量先例，不能直接成为论文创新主张。

## 三个容易误判的地方

### 1. 上传等待不会自动增加同一批次的完整 GPU 计算能耗

60 对相同请求与放置的控制中，TP 上行与等分上行的完整 GPU 增量完全相同。上传准备时间可以影响 SLO、后续接纳和组成，也可以把工作推到观察窗外；当前恒定相位功率模型没有将“等上传”转成额外 GPU 动态功耗。

因此，**保留无线—接纳—批次组成的耦合问题；淘汰“只因同批次等待更久就多耗动态 GPU 能量”的论证。** 这是模型结构的结论，不是硬件测量发现。

### 2. 预测更准不保证调度更安全或服务更多

16 GB、高提供负载的五场景均值：

| 长度输入 | 平均绝对误差/token | OOM 请求 | 窗口 Goodput |
|---|---:|---:|---:|
| cap | 122.29 | 0.0 | 1366.4 |
| 条件均值 0.75×cap | 79.08 | 454.6 | 1178.2 |
| 0.5×cap | 118.76 | 1403.0 | 679.4 |
| 真实长度 oracle | 0.00 | 0.0 | 1621.6 |

条件均值虽有较小平均误差，却会低估同步批次显存；误差在共同批次的最大值/容量约束下造成关联失败。oracle 读取未来信息，只是离线参照。24 GB 条件没有显示相同 OOM 机制，因此不能把 16 GB 的结论外推为所有容量下的预测收益。

当前 OOM 在上传后解析检测，没有计入真实 GPU 部分执行或恢复成本。这支持进一步检查联合可行性风险，不支持声称已解决或实测了 OOM 恢复问题。

### 3. 低总能耗可能只是少服务

高提供负载、cap 贪心、等分上行的五场景均值：

| 额外衰减 | Goodput | 窗口总能耗/J | 射频能耗/J |
|---|---:|---:|---:|
| 0 dB | 2577.2 | 20624.525 | 1.425 |
| 20 dB | 2571.6 | 20670.219 | 11.064 |
| 40 dB | 1338.6 | 17691.668 | 705.917 |

40 dB 下总能耗减少，同时服务量大幅损失，每个成功请求的成本反而恶化。射频占比也由约 0.00691% 变成约 3.99%，所以默认场景的极小通信占比不能外推到全部链路条件。

40 dB 是额外压力干预，尚无目标网络的实测分布支持。20 dB 下，全网格的配对 Goodput 均值变化在 −12.0 至 +41.533 个请求之间；不同负载和方法必须分别解释。PPO 的变化还包括冻结策略对新观测分布的响应，不全部是纯物理时延效应。

## 对当前研究问题的判断

| 候选问题 | 本轮证据 | 去留 |
|---|---|---|
| 同批次无线等待本身引起动态 GPU 能耗损失 | 完整 GPU 成本不变 | 当前模型下淘汰这条论证 |
| 无线时序改变接纳/组成，进而影响服务与能耗 | 压力网格有影响，受负载和方法影响 | 保留为条件诊断，先验证现实链路范围 |
| 同服务量下减少 padding 的能耗空间 | 六请求精确前沿与分组控制均有差距 | 保留，但不能把已有长度分组机制当创新 |
| 长度估计引发联合批次可行性风险 | 16 GB 存在，24 GB 未出现同样风险 | 保留容量/误差条件，继续核查已有鲁棒调度工作 |
| 仅调整现有卸载/带宽即可节省主要固定基线 | 默认 G4 固定基线占 71.197%，不可由现有动作改变 | 淘汰这条节能主张；不直接扩展已有休眠/DVFS 机制 |

当前最小候选问题可暂定为：**在固定模型、可见输出 cap 和端到端服务约束下，是否存在足够大的同服务量批次分组/节点放置能耗差距？** 本轮只证明解析模型中的条件差距；真实收益和与已有无线批处理研究的区别仍待验证。

## 在新算法之前还缺什么

现有模型令推理时间随 batch 大小线性增长，使用固定有效 FLOPS 和相位功率；主要批处理收益/损失来自 padding。它没有测量真实 GPU 上 batch 引起的利用率、显存带宽和功率变化。因此下一步应先校准这些量，确认约 2.52% 的总能耗示例收益是否稳健，并对选定的联合可行性机制做最近文献全文核查，再决定是否值得设计算法。当前结果不要求沿用 PPO。
