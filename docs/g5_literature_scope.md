# G5 文献重合清单的证据边界

本轮输入为用户提供的《七篇论文研读：研究空白、创新风险与下一步实验计划》。下面保留该讨论识别的重合风险，供解释实验时使用。**这是讨论来源清单，不是本轮重新完成的全文文献审计或领域新颖性检索。** 原始论文保留在仓库外，未复制到公共 Git 仓库。

| 材料 | 讨论归纳的主要层级/机制 | 对 G5 的约束 |
|---|---|---|
| TP-MPPO | 无线卸载、动态上下行资源、同步批次、Goodput | 作为模型与算法基线；不能把已有时延耦合直接命名为创新 |
| TPO-PPO | 系统能耗、节点/模型/任务计划和连续资源 | “无线通信 + 计算能耗 + PPO”存在直接重合风险 |
| TokenPowerBench | 推理性能与功率测量、阶段和部署配置 | 模拟积分不能替代硬件校准；阶段窗口定义要对齐 |
| DynamoLLM | 资源池、实例/并行配置、频率与请求分类 | 资源管理与长度预测本身不是空白 |
| throttLL’eM | KV/batch/性能预测、频率与伸缩 | 长度/缓存预测误差需要控制，不能仅加一个预测器作为主创新 |
| GreenLLM | 请求组织与阶段相关频率控制 | Prefill/Decode 区分本身已有先例 |
| BEAM | SLO 余量下的批处理参数和频率联合控制 | batch + DVFS + slack 的组合有高度重合风险 |
| Festina | 多节点放置、共享 GPU 配置、整合和迁移 | 多 GPU 放置与节能本身不能视作独有贡献 |
| Beyond the Cloud、Edge Inference…、ALPS、PowerSlider | 讨论仅核查过摘要/出版信息的进一步相关条目 | 本轮未重新验证题名、日期或全文机制；不据此作排他性结论 |

G5 只能验证当前模型中的影响与条件优化空间。要论证可投稿的新研究问题，仍需对选定机制的最近工作做有来源定位的全文核查，并校准目标硬件与链路。实验报告没有宣称上述文献未解决某问题，也没有声称本平台的新模块具备新颖性。

本轮直接核对的公开工具定义仅为 [Zeus 测量窗口](https://ml.energy/zeus/measure/) 与 [TokenPowerBench 仓库](https://github.com/chenxuniu/TokenPowerBench)，用于区分测量流程和模拟功率积分；不是对其整篇论文的复现。
